- **修复 EdgeOne 部署 `pnpm: not found`（exit 127）**：
  - 第一次猜测（nodeVersion 24.18.0 → 24.11.0）无效，重跑日志依旧。
  - 解包 `edgeone@1.6.44` 的 `cli.js` 分析确认真正原因：makers CLI **本地**探测 InstallCommand——`pnpm-lock.yaml` 存在且本机 `which pnpm` 成功就选 `pnpm install`，然后这条命令被丢到云端 sh 执行，云端容器没有 pnpm → 127。
  - `edgeone.json` 支持 `installCommand` 字段（会被映射为云端构建配置 InstallCommand）。最终方案：显式写 `"installCommand": "npm install"`（项目 `package-lock.json` 已核对与 package.json 一致：next 16.3.6 / react 19.3.0 / zod 4.6.5），避开自动探测。
  - 经验：EdgeOne makers CLI 路径下，lockfile 决定 install 命令的是「本地探测」，与控制台 Git 构建环境「预装 Node 自带 pnpm」是两套行为。

- **修复 EdgeOne 线上带尾斜杠路径 404**：线上实测规律 `/categories` 200、`/categories/` 404（404 响应带 Last-Modified/Etag，是预渲染 _not-found 静态文件直出）——EdgeOne 边缘对带尾斜杠目录路径做静态查找、不回退 SSR 函数；官方文档确认「不支持 Next.js 自身 rewrite/redirect，建议用 edgeone.json 配置」。
